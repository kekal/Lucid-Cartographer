## Decisions

- **D1 — Trip = collection with a view toggle.** A trip is NOT a new entity. The existing collection gains a "Trip View" toggle that *reveals* ordering, connecting lines, travel/dwell times, and the running timeline. Toggle off → plain POI collection. Smallest possible paradigm change. (User chose this explicitly over a separate Trip entity.)
- **D2 — Travel modes: Any/Air (incl. plane), Drive, Walk, Cycle.** Four modes. Drive/Walk/Cycle map to OSRM profiles; Any/Air uses straight-line (haversine) — also the universal fallback. Per-trip mode selection; per-leg override is an open question (see OQ).
- **D3 — Routing engine: OSRM + haversine fallback.** Self-host OSRM for real road duration matrix + road-shaped geometry; fall back to straight-line haversine when OSRM is unavailable or for Air legs. Google Routes API is an OPTIONAL bring-your-own-key add-on, never the default. (Advised by parent; user accepted.)
- **D4 — Reject Google Maps scraping for travel times.** Explicit Google Maps Platform ToS breach (§3.2.3) + fragile bot-detection (TLS fingerprinting, residential-proxy arms race). Rejected despite the app already owning a Playwright scraper. Rationale preserved in `addendum.md`.
- **D5 — No "day" entity / no multi-day buckets.** An overnight is modeled as a hotel POI with a long dwell time; a night flight is just a travel leg. The itinerary timeline accumulates linearly. (User: "Days are not an entity considered by this tool.")
- **D6 — Roundtrip with designated Start/Finish.** Every trip has a designated Start Stop; Finish defaults to the Start Stop (closed loop) but may be set to a different stop. The auto-optimizer pins Start and Finish.
- **D7 — Auto-ordering = in-process Nearest-Neighbor + 2-opt in C#.** No external solver. Operates on the OSRM duration matrix; pins Start/Finish. LLM/MCP layer adds soft constraints, then 2-opt cleans up. Detail in `addendum.md`.
- **D8 — Map line rendering phased.** Phase 1: straight numbered polylines (Leaflet `L.polyline`, near-zero effort). Phase 2: OSRM road geometry per leg. Both in v1 scope but straight-line is the floor.

## Advanced Elicitation — Assumption Audit (2026-06-11)
Ran Assumption Audit over the draft. Three red-risk assumptions all attacked the "real travel time for far-apart legs" promise. Shore-ups applied:
- **D9 — Air legs get manual Travel-Time entry; unentered Air time is a badged placeholder, not an estimate.** Rationale: plane time ≈ speed×distance is off by an order of magnitude (≈90% fixed airport overhead). Pulls the Air slice of per-Leg override into v1 (rest deferred). (FR-8, FR-13)
- **D10 — Haversine fallback also fires on "engine reachable but no route / out-of-coverage,"** not just engine-down. Rationale: region-scoped OSRM extract means cross-region Drive legs return no route and would otherwise silently fail. (FR-10, §12 coverage-boundary note)
- **D11 — Dwell-on-membership tradeoff made explicit** as an Open Question (no POI-level default to seed from). Kept the membership model (D-A6); surfaced rather than silent. (§8 OQ7)
