## What went well

1. **The seam investment from Epics 1–3 paid off — Epic 4 was almost pure addition.** `OsrmTravelTimeProvider` slotted into the existing per-leg `ITravelTimeProvider` contract; the background compute loop, the cache upsert (Manual/Measured protection), the degradation branch, and the Estimated→Measured recompute mechanism were **reused unchanged**. Story 4.1 changed exactly one line of existing wiring (the hard-coded provider registration → a config switch) and added three new files. Story 4.2 activated Phase-1 scaffolding (`drawTripLegs`'s reserved `measured` branch, the `.trip-leg-measured` CSS, the `StateChanged`→redraw path) rather than building new machinery.
2. **Degrade-by-throwing was the right architecture (A6 closed cleanly).** Routing OSRM's no-route/unreachable/timeout/HTTP-error/unconfigured-profile cases through a thrown `OsrmRouteUnavailableException` into the *existing* `catch (Exception)` (TRIP-DEGRADE-01) gave graceful degradation, observability, and the "never blank" guarantee **for free** — no second fallback path, no change to the background service. The real OSRM no-route signal (A6 carry-in) landed without new degradation code.
3. **A9 (directional/asymmetric cache) honored end-to-end.** Each `A→B` leg is its own `/route` query; `A→B` is never mirrored onto `B→A`. OSRM Drive routes can be genuinely asymmetric (one-way streets) and the directional `RouteSegment` cache + the Story 3.1 full-tour-cost 2-opt are already correct for that — Epic 3's foresight paid off the moment a genuinely asymmetric provider arrived.
4. **The fresh-context adversarial review earned its keep again — both stories.** It caught a real correctness bug in 4.1 (a `code:"Ok"` OSRM response with **no geometry** was silently persisted as a `Measured` row that `Upsert` never re-invalidates → would permanently starve 4.2's road line) and an untested seam in 4.2 (`RoutingAttributionHtml` had no asserting test). The 4.2 review also independently *verified* the two highest-risk paths (the live-upgrade dedup and attribution surviving a viewport flip) held — turning "the dev says it works" into "the reviewer traced it and it works."
5. **Opt-in infra discipline.** The OSRM sidecars are version-pinned (`v6.0.0`, not `:latest`) and gated behind a compose `profiles: ["osrm"]` so `docker compose up` starts none of them; `docs/osrm.md` documents extract prep + flip-on. NFR7 (no egress — self-hosted), NFR8 (ODbL attribution), and NFR9 (no cost by default) all satisfied; the default deployment carries zero new infra.

## Challenges & recurring patterns (the lessons)

1. **The "Measured row that never re-invalidates" trap (new lesson, A10).** `Upsert` deliberately never overwrites a `Measured` row (so a good road result sticks) — but that same protection means a **defective** Measured row (Ok-but-no-geometry) is permanent and invisible to recompute. The fix was to make the provider refuse to emit a Measured result it can't back with geometry (throw → degrade). **Lesson: a "sticky"/never-invalidated cached state must be validated *at the point of writing it*, because nothing downstream will ever correct it.** → A10 below.
2. **The A3 integration-host gate bit again — and was caught again.** Story 4.2 needed the active provider's attribution in the VM, which meant injecting `ITravelTimeProvider` into `TripViewModel` — but the **parameterless** `AddTripServices()` overload (the integration-host seam) registers no provider, so a required ctor dependency would crash the host. Resolved exactly as the A3 standing gate prescribes: an **optional** ctor param + registering the dependency-light Mock in the parameterless overload, then running the Trip integration filter to confirm the host still boots. This is the 2.1/2.4/3.1 failure mode for the fourth time; the gate held.
3. **Config read in two places (4.1 MED-2, accepted).** The OSRM HTTP timeout is set on the named `HttpClient` at registration by reading `TravelTime:Osrm:RequestTimeoutSeconds` directly, while `OsrmOptions.RequestTimeoutSeconds` also binds the same key. No divergence (same key, same default), but it is mild dead surface — accepted. **Lesson: when a value must be consumed both at DI-registration time (pre-`IOptions`) and as a bound option, note explicitly that they read one key, or the bound property reads as authoritative when it isn't.**
4. **JS rendering stays a harness blind spot.** The decode→solid-road `L.polyline` and the attribution-control DOM are JS-only; `StubMapService` no-ops Leaflet, so the actual visual is verified by inspection, not assertion (same limitation as the 1-2/1-4 map defers). We pushed the *testable* boundary as far up as it goes — geometry through the projection (unit) and through the DTO to the service boundary incl. the upgrade re-push (integration), and provider `Attribution` (unit) — and recorded the rest honestly. The standing want is a JS-capable (Playwright-DOM) harness.
