## What went well

1. **The single-write-path investment paid off twice.** Both new ordering paths (TSP-Sort #3 and MCP #4) plugged into the existing `ArrangeWithPins` → `Renumber` → `SetOrderAsync` chain with **no second writer** and no new pin logic. AR-11's "one method, four triggers" held exactly as designed — the hard work was done in Epics 1–2.
2. **Pure, DB-free algorithm core.** `TspSolver` takes a cost matrix + pin indices and returns a permutation — fully unit-testable (zig-zag untangle, pin honouring, roundtrip vs open, never-worse, asymmetric correctness, N=30 perf) without a database. Keeping the heuristic separate from the I/O was the right call.
3. **A5 closed cleanly.** The MCP coord-invalidation TODO (deferred since 2.4, promoted to 3.2) was resolved with a real behavior + 3 regression tests; the `#pragma warning disable MA0026` is gone.
4. **A3 standing gate did its job.** Every DI/VM-ctor-adjacent change (3.1: new `IDistanceMatrixService` dependency on `TripOrderingService`; 3.2: VM dwell-delegation) was followed by the full Trip integration run. The 3.1 DI risk (integration host composing `TripOrderingService` by hand) was anticipated and pre-empted by registering `DistanceMatrixService` in the **parameterless** `AddTripServices()` overload — no integration-host crash this epic.
5. **Zero-friction MCP surface.** `WithToolsFromAssembly()` auto-discovers `TripTools` — 7 new tools landed on the authenticated `/mcp` with **no Program.cs change and no new auth surface** (AC2 satisfied structurally).

## Challenges & recurring patterns (the lessons)

1. **Test-namespace shadowing (new lesson, A8).** New test files placed under `Tests/Services/` were initially declared `namespace LucidCartographer.Tests.Services` — which **shadowed** every relative `Services.*` reference in the test assembly (`IntegrationTestBase`, `DataSourcesPageTests`), breaking the build with confusing `CS0234` errors. The codebase convention is `namespace LucidCartographer.Tests` regardless of folder. → **Lesson A8 below.**
2. **The directional cache breaks textbook 2-opt (new lesson, A9).** `RouteSegment` is directional ([TRIP-CACHE-01]); reversing a tour segment flips every internal edge's direction, so the cheap boundary-edge 2-opt delta is *invalid* for an asymmetric matrix. Caught during implementation and handled with full `TourCost` evaluation per trial (fine for N≤30). With the Mock the matrix is symmetric today, but OSRM (Epic 4) can be genuinely asymmetric — the correct evaluation is already in place. → **Lesson A9 below.**
3. **DI dependency placement recurs (A3 class).** Adding a dependency to a service the integration host constructs by hand is the exact 2.1/2.4 failure mode. Pre-empted this epic, but it is a *standing* trap — every new injected dependency on a Trip service must register in the overload the host calls. A3 stays a non-negotiable gate.
4. **Reviewer caught honesty/robustness gaps both stories.** 3.1: a no-op sort still announced a reorder (fixed to match `MoveStopToAsync`'s no-op silence). 3.2: an MCP **input** typed `IReadOnlyList<int>` is a schema-binding portability risk vs `int[]` (fixed). Small, but exactly the kind of thing the fresh-context adversarial pass exists to catch.

## Significant discovery → promoted action item

**The OrderIndex / pin write-path atomicity defer is now genuinely multi-path.** Through Epics 1–2 the only `OrderIndex` writer ran on the Blazor circuit, which serializes per-user calls; the split read-validate-write (only `SaveChangesAsync` under `SqliteWriteLock.Gate`) was acceptably safe. **Story 3.2 makes MCP the first off-circuit caller** — an MCP request can now race a UI drag, or another MCP request, with no circuit to serialize them. Both story reviews flagged this. For the single-user self-hosted target the realistic lost-update risk stays low (and `PoiCollection.Version` still guards concurrent pin writes), but the entry surface is now legitimately concurrent. → **Action item A7: evaluate a single gated read-validate-write transaction** before any multi-user/shared-deployment scenario.
