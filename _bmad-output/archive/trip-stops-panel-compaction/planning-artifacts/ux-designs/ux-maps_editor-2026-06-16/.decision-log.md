# UX Decision Log — Trip stops panel compaction

Mode: **Update** — targeted redesign of the desktop Trip View stop-list header
(`LucidCartographer/Components/Shared/Trip/TripStopList.razor`) plus the dwell /
per-leg duration inputs. No prior DESIGN.md/EXPERIENCE.md spine exists for this
brownfield app; this run captures the delta only.

Facilitator: bmad-ux · User: Yurik · Date: 2026-06-16

## Source problem (user, annotated screenshot)
1. The header has 5 static full-width rows eating vertical height.
2. Duration editboxes (per-leg "movement" + per-POI "staying"/dwell) should be
   time pickers — no AM/PM, no hours cap.
3. Stop count + total travel time labels/values are split to the far left and far
   right of their rows — looks ugly.
4. "Sort in Traveling Salesman order" and "Recompute travel times" are text links;
   should be buttons.

## Current state (verified in code)
Desktop `TripStopList.razor` header = 5 stacked bordered rows:
- L13 title + count (justify-between)
- L35 "Total travel time" label + value (justify-between)
- L46 TSP-Sort + Recompute as `text-primary hover:underline` links
- L79 Start time / Time limit (HH:MM ≤24h) / Finish by inputs
- L145/L167 OSRM/estimate info banner (conditional: only on Mock/fallback provider)

Dwell input (L360): `<input type=text>` masked HH:MM, pattern caps hours 0–23.
Per-leg time (`LegConnector.razor` L24): `<input type=number>` in **minutes**, max 65535.

## Decisions
- **D1 — Header → two slim rows (+ conditional OSRM row).**
  - Row 1: merge old rows 1+2+3. Left: `Trip stops · {N} stops · {total}` inline
    (fixes #3 — no left/right split). Right: Sort + Recompute buttons.
  - Row 2: Start / Limit / Finish inputs stay inline & visible (one wrapping row).
  - OSRM/estimate note: keeps its own row, UNCHANGED behavior — already conditional,
    so it auto-hides once a real routing engine (OSRM) is active. (User: "it should
    be in separate row as now but disappear when OSRM will work.")
- **D2 — Sort / Recompute become buttons** (outlined, icon + label; keep the
  `disabled` while-computing state and existing aria-labels).
- **D3 — Duration inputs → masked HH:MM with ▲▼ steppers, hours UNCAPPED.**
  - Applies to BOTH the per-POI dwell input and the per-leg movement-time input.
  - Per-leg input converts from a minutes number field to the HH:MM control
    (convert at the UI edge only; VM keeps canonical minutes/seconds).
  - Lift the `([01]?[0-9]|2[0-3]):[0-5][0-9]` 24h pattern → allow 1–3+ hour digits
    (e.g. `125:30`). Minutes still `[0-5][0-9]`.
  - Steppers: ▲▼ adjust ±5 min per click; **Shift+click = ±1 hour** (D4, confirmed).
    Never go below 0; per-leg has no upper clamp beyond storage (seconds).

- **D4 — Stepper increment = 5 min, Shift = 1 hour.** (User confirmed 2026-06-16.)

- **D5 — Limit ⇄ Finish-by are one linked value; Limit is a duration picker.**
  (User 2026-06-16: "Setting Finish by and Limit should be connected, cause it's
  actually the same value"; "Limit should be duration time picker as other durations";
  "editing of one value should reflect the other.")
  - `Limit` and `Finish by` are two views of ONE canonical value (`TimeBudgetMinutes`).
  - `Limit` becomes the SAME uncapped HH:MM + ▲▼ stepper control as dwell/leg (D3) —
    drop the ≤24h cap. This removes the old reason the two were split (the deadline
    path was kept solely to own the >24h horizon; an uncapped duration covers it now).
  - **Canonical = the duration (Limit).** `Finish by` = `start + Limit` (derived view).
  - **Bidirectional on edit:** editing `Limit` updates the `Finish by` display;
    editing `Finish by` back-computes `Limit` = `Finish − start`. Both persist the
    same canonical minutes.
  - When `start` later changes, `Finish by` re-derives (= start + Limit); the duration
    is unchanged. (Edit-time mirroring is the user's explicit ask; this start-change
    derivation is the consistent default for "Limit is a duration.")
  - `Finish by` still requires a `start` (disabled + hint when absent, as today);
    `Limit` can be set as a pure duration with no start.
  - Supersedes the current one-shot deadline→minutes conversion (old L104–116 note).
