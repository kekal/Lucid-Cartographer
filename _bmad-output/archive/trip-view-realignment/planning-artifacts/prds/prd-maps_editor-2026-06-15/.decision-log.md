- **NEW REQUIREMENT — per-leg travel mode (Feature F).** Original request was different *movement types within a trip*; build shipped a single **per-trip** mode (`PoiCollection.TravelMode`) — EXPERIENCE.md scoped v1 to "one mode per trip." Yurik: per-trip mode is meaningless (drive into town, then walk 1 km). **Note:** Yurik corrected my first framing ("trip default + per-leg overrides / inherit") as *"incorrect documentation generation over the request."* The exact requirement:
  1. **Every movement between two POIs has its own travel type** (per-leg mode).
  2. **New movements created by recalculation / manual reorder / TSP / add-remove become undefined ("Any")** — no auto-assigned mode, **no automatic estimate**.
  3. **Flight (Any/Air) is never auto-estimated — user-specified (manual) only.** Ground modes (Walk/Drive/Cycle) are what yield an automatic Estimated/Measured time.
  - No trip-level default that silently drives legs (inheritance explicitly rejected). The existing `Any/Air` mode already = "no auto-estimate, manual-only," so "undefined/Any" maps onto it. Data model is ready: `RouteSegment.TravelMode` is already part of the directional cache key (TRIP-CACHE-01); per-leg mode persists on the stop's outgoing leg (e.g. nullable `PoiCollectionItem.OutgoingTravelMode`) + a small migration. Largest item (schema + projection + UI). Scope: Yurik [No preference] → **included as Feature F** in this PRD (fits the "make Trip View honest" theme); will be its own epic.

Overnight modeling stays out of scope. Appended as Feature G to avoid renumber churn; reorder near the timeline (Feature D) at polish.
- **NEW REQUIREMENT — budget as duration OR finish datetime (Feature G, FR-24/25).** Yurik: time budget should be enterable both as **time (time picker, HH:MM duration)** and as a **datetime picker (date+time of the finish)**.
