# Epic 3 Retrospective — Retire OSRM (removal & migration)

**Date:** 2026-06-24 · **Mode:** YOLO (autonomous, no tmux — Windows manual cycle)
**Feature:** Clean, safe removal of the superseded hand-rolled OSRM routing path now that Valhalla
is the measured provider — artifact deletion, warn-and-fall-back for a retired provider id, and a
one-time invalidation of stale OSRM cache rows.

## Outcome

Epic 3 (3 stories) complete — all `done`, all reviewed **Approve** with **0 Critical/High/Medium**
findings. The codebase now carries **no dead routing path**: every hand-rolled OSRM artifact is gone,
a now-retired `TravelTime:Provider=Osrm` (or any unknown id) boots cleanly into the smart-haversine
default with a loud startup warning instead of bricking, and a one-time startup migration purges stale
`Source=OSRM` cache rows so they recompute under the active provider — never touching `Manual` rows.
Full suite stayed green at 1190/1190 throughout; build clean under `TreatWarningsAsErrors`.

- **3.1** Prominent warn-and-fallback for retired/unknown provider ids — added a pure, testable
  `TripServicesExtensions.ClassifyProvider(id)` → `{Default, Valhalla, RetiredOrUnknown}` and switched the

  default and emits a prominent `LogWarning` (via a bootstrap logger, since selection runs before the host
  logger exists) naming the offending value and stating routing is now **ESTIMATED, not MEASURED**. Never
  fail-fast. Migration callout added to `docs/valhalla.md`. (FR-15, AD-7)
- **3.2** One-time invalidation of OSRM cache rows — added
  `StartupCleanupService.PurgeOsrmCacheRowsCoreAsync` (extracted-static, testable, returns count), wired as
  step 6 of `StartAsync` under `SqliteWriteLock`. Deletes every `RouteSegment` where `Source == "OSRM"`
  (**literal**, with a code comment noting the constant is removed in 3.3) AND `Fidelity != Manual` (a
  structural belt over `[TRIP-MANUAL-01]`). Logs the count, idempotent/self-retiring; purged legs refill via
  the existing missing-row trigger. (FR-16, AD-6)
- **3.3** Delete all hand-rolled OSRM artifacts — removed `OsrmTravelTimeProvider.cs`, `OsrmOptions.cs`,
  `OsrmRouteUnavailableException.cs`, the `TravelTimeSource.Osrm` constant, the named `"osrm"` HttpClient

  `TravelTime:Osrm` appsettings section, `OsrmTravelTimeProviderTests.cs`, the OSRM provider end-to-end test

  `UiStrings.TripRoutingAttributionOsm` with no dangling reference. **Closure beyond the literal FR-14 list

  `<EmbeddedResource>`, `.dockerignore` negation, `DocsEndpoints` route `/docs/valhalla.md`, `Program.cs`

  capability seam** (`ProducesMeasuredFidelity != true`) rather than the deleted source string; retargeted

## Lessons / Action Items

- **A10 — The Epic 2 carry-over #1 (per-leg precision decoder) was resolved by *removal*, not new code.**
  Epic 2 flipped `leafletInterop.js` to `1e-6` and flagged that OSRM (precision-5) geometry would mis-decode
  until Epic 3, with a per-leg precision hint as the planned follow-up. Removing OSRM — the **only**
  precision-5 source — makes `1e-6` unconditionally correct, so the follow-up evaporated: the fix was a
  one-line comment update, not a new precision-hint mechanism. *Standing value:* a flagged tech-debt item
  whose root cause is a soon-to-be-deleted component is often best left until the deletion moots it, rather
  than building a bridge you'll tear down.
- **A11 — Keying the purge on the literal `"OSRM"` decoupled 3.2 from 3.3's deletion order.** Because the
  FR-16 migration matches `Source == "OSRM"` (string) and not `TravelTimeSource.Osrm` (constant, deleted in
  3.3), the two stories were independently completable and the purge survives the constant's removal intact.
  *Standing rule:* a data migration that outlives the code it cleans up after should pin the on-disk value
  literally, with a comment explaining why the constant is intentionally not used.
- **A12 — Gate UI on the capability seam, not on provider identity.** `RecommendsOsrm` keyed on
  `provider.Source != TravelTimeSource.Osrm` — fragile (any new measured provider would have wrongly kept
  recommending) and a hard blocker once the constant was deleted. Re-expressing it as
  `RecommendsMeasuredProvider` gated on `ProducesMeasuredFidelity != true` is both the natural rename target
  and strictly more correct: it now suppresses for *any* measured provider. This mirrors Epic 2's A6 lesson
  (capability flag over config string) — the same seam paid off again at the UI edge.
- **A13 — "Delete all artifacts" had a larger real surface than the FR bullet list.** FR-14 enumerated the
  obvious deletions (provider/options/exception/DI/compose/tests/doc), but a truly clean removal also had to
  retire the in-app "How to enable OSRM" note + its served `docs/osrm.md` route + embedded resource + csproj
  + `.dockerignore` negation, all of which pointed at a now-deleted doc. The epic intent ("no dead routing
  path", "no dangling reference") made this unambiguous, so it was handled inline by retargeting to Valhalla
  (consistent with FR-13/AD-9, which already made `docs/valhalla.md` replace osrm.md's role). *Standing rule:*
  a deletion FR's bullet list is the floor, not the ceiling — chase every reference to a thing being deleted,
  especially user-facing copy and routes that link to deleted docs.
