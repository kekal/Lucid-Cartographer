## Lessons / Action Items

- **A5 — "Mirror OSRM exactly" was the lowest-risk path to a new provider.** `ValhallaTravelTimeProvider`,
  `ValhallaOptions`, and `ValhallaRouteUnavailableException` were shaped 1:1 against the OSRM trio, so
  the only genuinely new surface was the JSON contract (POST vs GET, `{lat,lon}` vs `lon,lat`,
  `trip.summary` vs `routes[].duration`). *Standing value:* when a working sibling exists, clone its
  shape and concentrate review on the deltas — here the coordinate-order inversion (locked by a de-DE
  invariant-culture test) was the single highest-bug-risk line and got pinned.
- **A6 — A capability flag, not a config string, gates the measured upgrade (AD-2).** The recompute
  trigger reads `provider.ProducesMeasuredFidelity` to decide whether to *broaden* the pending-leg
  predicate. Mock (=false) collapses to the legacy "any row ⇒ skip" rule, so it can never re-churn its
  own estimates into an infinite loop; Valhalla (=true) opens the upgrade arm. *Standing rule:* gate
  behavior on a typed capability the provider declares about itself, not on a string the DI layer
  happens to have selected.
- **A7 — Epic 1's single edges paid the degrade dividend.** Because the estimate path
  (`EstimatedTravelTime.Compute`) and the upsert guard (`[TRIP-MANUAL-01]`) are each a single DRY edge,
  Story 2.3's per-leg degrade-to-`EstimatedFallback` and the Manual/Measured no-downgrade guarantee
  needed **no new guard code** — 2.3 broadened a predicate and 2.6 only had to *test* the existing
  guards (the NFR-10 row-survival test passed against code already in place). The Epic 1 → Epic 2
  degrade-target dependency was satisfied with zero added branching.
- **A8 — docker was unavailable; compose/tile-build validated structurally, three items deferred to
  operator-verify.** With no Docker daemon, Story 2.5's service was validated by YAML well-formedness +
  structural assertions (default service set excludes `valhalla`; profile set includes it) and Story
  2.6's no-egress claim by stub-handler reflection tests — not by a live container. Three artifacts are
  consequently marked `[ASSUMPTION]`/operator-verify and carried as backlog (see below). *Standing rule:*
  when an external runtime is absent, prove what static analysis can and flag the rest explicitly in the
  operator doc rather than asserting unverified numbers.
- **A9 — The precision-6 decoder flip is a deliberate, time-boxed trade-off (Epic 3 follow-up).**
  `leafletInterop.js` was flipped `1e-5 → 1e-6` (Option 1) because the deployment default is Mock and
  OSRM is opt-in and being retired, so no precision-5 source is active. The cost — OSRM (precision-5)
  geometry mis-decodes at ~1/10th scale while it shares this single decoder — is documented in the JS
  comment. A robust per-leg precision hint was intentionally deferred to Epic 3. *Flagged below.*

## Backlog / Epic 3 carry-overs

1. **Per-leg precision hint for the polyline decoder (Epic 3).** Replace the global `1e-6` flip with a
   per-leg precision so OSRM (precision-5) geometry decodes correctly until OSRM is removed — or moot it
   by completing the OSRM removal first. (From A9 / Story 2.2.)
2. **Operator-doc note: `use_tiles_ignore_pbf=True` does not auto-rebuild on `.pbf` change.** The
   gis-ops image reuses existing tiles for fast restart; a `tile_urls`/`.pbf` change is only picked up
   after `./appdata/valhalla` is cleared. This is a nuance vs FR-11's "auto-rebuilds when the .pbf
   changes" wording — add the clear-the-volume step to `docs/valhalla.md`. (Story 2.5 LOW.)
3. **Pin the Valhalla image by `@sha256:` digest.** Currently `:3.5.1` (AC-permitted specific tag) because
   docker was unavailable to resolve the canonical digest; operator can append the digest. (Story 2.5 LOW.)
4. **Measure and finalize the one-time tile-build cost (OQ-3 / NFR-9).** The time/disk/RAM figures in
   `docs/valhalla.md` are `[ASSUMPTION]`/operator-verify because docker was unavailable to measure them.
   Replace with measured values. (Story 2.6.)
5. **Already scoped as Epic 3 (no action needed here):** OSRM artifact deletion (FR-14, AD-9 string +
   provider/options/exception/DI/compose/docs), retired-`Provider=Osrm` warn-and-fall-back (FR-15, AD-7),
