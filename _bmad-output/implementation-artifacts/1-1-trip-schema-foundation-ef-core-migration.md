# Story 1.1: Trip schema foundation (EF Core migration)

Status: done

## Story
As a LucidCartographer maintainer,
I want the database schema extended with trip fields and a route-segment cache table,
so that every later Trip View story has the persistent shape it needs without a second migration.

## Acceptance Criteria

1. A single new EF Core migration `AddTripPlanning` is created (generated via `dotnet ef migrations add`, never hand-written from scratch) and is applied at startup through the existing `MigrateAsync` path in `Services/StartupCleanupService.cs` — never `EnsureCreated`, and the migration is never hand-edited after it has been applied to any database. [Source: epics.md#Story-1.1 AC group 1 & 3; architecture.md#D1]

2. `PoiCollectionItem` gains two new columns:
   - `OrderIndex` (`int`, non-nullable) — the Stop Order within a Trip. It is **1-based** (1..N, contiguous, gap-free, unique per Trip). This story only persists the column; seeding/compaction logic belongs to Story 1.2. Existing rows must receive a sane default on apply (see Dev Notes — backfill). [Source: architecture.md#D1; architecture.md#Format-Patterns (1-based OrderIndex); AR-11]
   - `DwellMinutes` (`int?`, nullable) — per-Stop dwell time stored in **minutes**, on the join (membership) so the same POI carries a different dwell across Trips. [Source: architecture.md#D1; AR-11 (dwell in minutes)]

3. `PoiCollection` gains six new columns:
   - `TravelMode` (string-persisted `TravelMode` enum: `AnyAir`, `Drive`, `Walk`, `Cycle`).
   - `StartPoiId` (`int?`, nullable FK to `Poi`).
   - `FinishPoiId` (`int?`, nullable FK to `Poi`; null ⇒ roundtrip).
   - `TripStartTime` (nullable `DateTime?`).
   - `TimeBudgetMinutes` (`int?`, nullable; soft-overrun flag, stored in **minutes**).
   - `TripViewEnabled` (`bool`, non-nullable, default `false`; per-Collection persistence — D10).
   [Source: epics.md#Story-1.1 AC group 1; architecture.md#D1; architecture.md#D10]

4. A new `RouteSegment` entity (the Leg cache) exists, keyed on the composite `(FromPoiId, ToPoiId, TravelMode)`, with columns:
   - `FromPoiId` (`int`), `ToPoiId` (`int`) — directional: A→B and B→A are **distinct rows**; the pair order is never collapsed.
   - `TravelMode` (string-persisted `TravelMode` enum) — part of the key.
   - `DurationSeconds` (`int`) — travel time in **seconds**.
   - `DistanceMeters` (`double`) — distance in **meters**.
   - `GeometryPolyline` (`string?`, nullable; null = no road geometry → dashed/muted render later).
   - `Fidelity` (string-persisted `Fidelity` enum: `Measured`, `Estimated`, `Placeholder`, `Manual`).
   - `Source` (`string`) — the provider/source identifier.
   - `ComputedAt` (`DateTime`).
   - `Version` (`int`, optimistic-concurrency token, matching the existing `[ConcurrencyCheck]` precedent on `Poi`/`PoiCollection`).
   [Source: epics.md#Story-1.1 AC group 1; architecture.md#D1; architecture.md#Naming-Patterns; architecture.md#Format-Patterns (directional key, canonical units)]

5. The `TravelMode` and `Fidelity` enums are persisted **as strings** with an EF check constraint restricting each column to the allowed value set (matching the `PoiCategory` string-constant precedent) — they are **NOT** int-backed. The check constraints cover every column that stores each enum: `PoiCollection.TravelMode`, `RouteSegment.TravelMode`, and `RouteSegment.Fidelity`. [Source: epics.md#Story-1.1 AC group 2; architecture.md#Naming-Patterns; AR-11]

6. Indexes exist on:
   - The `RouteSegment` cache key `(FromPoiId, ToPoiId, TravelMode)` (this is the composite primary key, so it is indexed by definition; if a non-PK lookup index is preferred, it must cover the same key).
   - The new FK columns: `PoiCollection.StartPoiId`, `PoiCollection.FinishPoiId`, `RouteSegment.FromPoiId`, `RouteSegment.ToPoiId`.
   [Source: epics.md#Story-1.1 AC group 2; architecture.md#D1 (indexes on cache key and FK columns)]

7. The build passes with `TreatWarningsAsErrors=true` and introduces **no group-B analyzer violations** (`MA0002`, `MA0015`, `MA0046`, `MA0047`, `MA0074`, `VSTHRD200`); no `ConfigureAwait(false)` is added. New design decisions in the modified/new source carry searchable **`TRIP-*`** comment codes. [Source: epics.md#Story-1.1 AC group 3; project-context.md#Build-&-Language-Discipline; AR-11]

8. The `AppDbContextModelSnapshot.cs` is regenerated by the `dotnet ef migrations add` run and committed alongside the migration (it is a generated file — do not hand-edit it). [Source: architecture.md#D1; existing Migrations/ discipline]

## Dev Notes

### Architecture patterns / constraints that apply
- **Migration discipline (ARCH-CRIT-01):** schema changes go in via a new EF migration applied at startup through `Services/StartupCleanupService.cs` → `db.Database.MigrateAsync(...)` (line 82). Never `EnsureCreated`; never hand-edit an applied migration (only the documented raw-SQL backfill block is added before first apply). [Source: project-context.md#Conventions-Agents-Miss; architecture.md#D1; Services/StartupCleanupService.cs:11,82]
- **String-persisted enums with check constraints:** `TravelMode`/`Fidelity` are persisted as strings and constrained at the DB level, matching the `PoiCategory` string-constant precedent — NOT int-backed. Note the *current* codebase enforces `PoiCategory` only via `PoiService` validation (no DB check constraint today); the architecture deliberately upgrades the trip enums to also carry an EF check constraint (the `CK_Poi_*` constraints already in `AppDbContext` are the constraint-style precedent). [Source: architecture.md#Naming-Patterns; AR-11; Data/Entities/PoiCategory.cs; Data/AppDbContext.cs:46-54]
- **Canonical units (AR-11, non-negotiable):** `DurationSeconds` (seconds), `DistanceMeters` (meters), `DwellMinutes`/`TimeBudgetMinutes` (minutes). No unit conversion happens at this layer — storage only; UI-edge conversion is a later story. [Source: architecture.md#Format-Patterns; AR-11]
- **1-based `OrderIndex`** stored exactly as displayed (no 0-based + offset). [Source: architecture.md#Format-Patterns; AR-11]
- **Directional cache key:** `(FromPoiId, ToPoiId, TravelMode)` — A→B and B→A are distinct rows; never collapse. [Source: architecture.md#Format-Patterns]
- **Concurrency token:** `RouteSegment.Version` uses the same `[ConcurrencyCheck] int Version` optimistic-concurrency pattern already on `Poi` and `PoiCollection`. The `SaveChanges`/`SaveChangesAsync` override in `AppDbContext` increments `Version` for `Poi`/`PoiCollection` on modify — **do not** extend that override to `RouteSegment` in this story (cache-write ownership is a later story); the column simply exists. [Source: Data/AppDbContext.cs:133-172; Data/Entities/Poi.cs:95-96]
- **Build discipline:** warnings-as-errors, `Nullable=enable`, no group-B analyzer violations, no `ConfigureAwait(false)`. [Source: project-context.md#Build-&-Language-Discipline; AR-11]
- **TRIP-* comment codes** make trip decisions greppable, consistent with the existing `ARCH-*`/`IE-*`/`REVIEW-*` convention seen in source (e.g. `ARCH-CRIT-01` in `StartupCleanupService`, `REVIEW-24` in `AppDbContext`). [Source: architecture.md#Enforcement-Guidelines; project-context.md#Conventions-Agents-Miss]
- **Scope guard:** this story is schema/migration/entity-config/enums ONLY. No `Services/Trip/`, no ViewModel, no UI, no toggle, no ordering service, no provider, no background compute — those are Stories 1.2–1.7 / Epic 2. Other stories *consume* these entities. [Source: epics.md#Epic-1; architecture.md#Implementation-Sequence]

### Testing standards summary
- **Frameworks:** xUnit 2.9 + FluentAssertions 7 (+ Moq where needed). `InternalsVisibleTo("LucidCartographer.Tests")` is set — test internals directly. [Source: project-context.md#Technology-Stack; project-context.md#Testing-Rules]
- **EF Core InMemory caveat (critical for this story):** the project's `TestDbHelper.CreateFactory` uses `UseInMemoryDatabase`, which builds schema from the model and **never runs migration `Up()` and never enforces check constraints**. Therefore the `OrderIndex` backfill SQL and the `CK_*` enum check constraints **cannot** be verified on InMemory. They MUST be verified against **real SQLite** using an `:memory:` `SqliteConnection` + `IMigrator`, exactly as `LucidCartographer.Tests/Services/MigrationBackfillTests.cs` does for the `AddPoiEnrichmentRequested` backfill. Use that file as the structural template for `AddTripPlanningMigrationTests.cs`. [Source: LucidCartographer.Tests/Services/MigrationBackfillTests.cs:10-15,24-46; LucidCartographer.Tests/TestDbHelper.cs:12-14]
- **What to assert on real SQLite:** migration applies cleanly; new columns/table readable; `OrderIndex` backfill is 1-based/contiguous per collection in `AddedDate` order; constraint violations throw `SqliteException` for bogus `TravelMode`/`Fidelity`; both directional `RouteSegment` rows coexist.
- **Heavier integration (`IntegrationTestBase`, real `WebApplication` + Playwright + per-test temp SQLite) is NOT required** for this schema-only story — a focused migration test is sufficient. Reserve `IntegrationTestBase` for the UI stories that follow.
