## Lessons / Action Items

- **D1 — Canonical-units-at-the-edge held across the whole epic.** Every Epic 4 story converted at
  the component bridge (datetime-local ISO ↔ DateTime; HH:MM ↔ minutes; deadline−start → minutes
  once) and left the canonical `DateTime?`/`int?` fields and the timeline math untouched (NFR2). The
  reviews confirmed no accumulation-math change in any story. This is the cleanest pattern for
  input-affordance work: change the control, never the stored unit.
- **D2 — "Compute once" must store the RESULT, not the input.** 4.3's finish-by deadline persists
  only the derived `TimeBudgetMinutes` (no stored deadline, no `value` binding), so it provably never
  recomputes when the start/trip later change (TRIP-SCHEDULE-01). The review verified this at the
  logic level (there is nothing to recompute from), not just via the test. Pattern: a
  "computed-once goal" should leave no live input to re-derive from.
- **D3 — Locale display, invariant wire.** 4.1/4.2 keep the control `value`/wire format invariant
  (ISO `yyyy-MM-ddTHH:mm`) while DISPLAY (the date on a later-day arrival) is locale-driven
  (`CultureInfo.CurrentCulture`, no hard-coded order). Tests build expected strings from the same
  culture+specifiers, so they're locale-robust. A self-review fix unified the clock to 24h across
  same-day and later-day rows (was drifting to locale 12h/24h).
- **D4 — Verify-and-fix stories still earn their tests.** 4.5 changed NO production code (the spine
  was already correct) but added the missing readout coverage (3 states + no-data-loss + multi-day
  footer date). The footer-scoped assertion helper was needed because per-row Finish controls also
  carry "Finish" in their aria/title — a whole-markup `NotContain` would have false-negatived.
  *Lesson:* scope readout assertions to the element under test.
- **D5 (carried) — shared-layer changes reach mobile by nature.** 4.2's date-aware formatting and
  4.1/4.3/4.4's canonical fields keep `MobileTripPanel` correct; the mobile suite (53→55) stayed
  green throughout. Only mobile *controls* (datetime-local start, HH:MM limit/dwell, per-leg pill)
  remain deferred to the mirror phase.
