## Lessons / Action Items

- **C1 — The adversarial review caught the two real bugs of the epic; keep it mandatory.**
  - Story 3.3 **H1**: Set/Clear Finish flips the trip shape (closing leg appears/vanishes) but
    `SetOrderAsync` read the pin once (already mutated), so the old vs new successor maps used the
    same shape and missed the closing-leg mode reset. Fixed by threading the prior shape
    `(bool Provided, int? Finish)` — and the **bool flag was essential** because a prior Finish of
    null is a real roundtrip shape, not "unsupplied" (a plain `int? ?? current` conflates them; the
    `SetFinish` test caught that mid-fix). *Lesson:* when computing old-vs-new state in a sole
    writer, capture the OLD state explicitly before the mutating caller overwrites it; nullable
    "not supplied" sentinels are a trap when null is a valid value.
- **C2 (ACTION ITEM A11) — Mode change orphans a Manual override row.** Found in the 3.5 review:
  setting a Manual time on a leg, then changing that leg's mode via the 3.4 pill / `set_leg_travel_mode`,
  leaves the Manual `RouteSegment` row stranded at the OLD mode key. Harmless to DISPLAY (projection
  keys by current mode) and pre-existing in shape, but a stale row + a "my manual time vanished"
  papercut, and switching back resurfaces it. **Action:** a follow-up should make
  `SetOutgoingTravelModeAsync` (or a sweep) delete/migrate a leg's Manual row when its mode changes.
  Tracked tech-debt; not blocking (no wrong value shown).
- **C3 — Three projection sites must stay exact mirrors.** The leg set (consecutive pairs +
  roundtrip closing leg), the open/roundtrip shape decision, and the per-leg `(From,To,Mode)` cache
  lookup are duplicated in `TripViewModel.BuildLegs`, `TravelTimeComputationBackgroundService.DirectionalPairs`,
  and MCP `get_trip`. They are byte-for-byte consistent now (reviewer verified), but this is a
  standing divergence risk. *Lesson:* a change to leg shape/mode-keying must update all three; a
  shared helper would reduce the risk (candidate refactor, not required).
- **C4 — Sole-writer discipline extended cleanly.** `OutgoingTravelMode` is mutated only inside
  `TripOrderingService` (the order/reset writer + the new `SetOutgoingTravelModeAsync`), reused by
  the VM pill and the MCP tool. Keeping one writer made the reorder-reset rule and the MCP path
  trivially consistent. Keep new mutable Trip columns single-writer.
- **C5 — ADD-only migration sequencing (Major #1) was correct.** Splitting "add the column" (3.1)
  from "drop the dead `PoiCollection.TravelMode`" avoided a broken intermediate build. The column
  remains as the RD1a dead-column fallback (still written by the inert mobile selector); a true
  drop is optional cleanup, deferred. `has-pending-model-changes` confirmed model↔snapshot
  consistency at 3.1.
- **C6 (carried, held) — Trip integration filter after every VM/ordering/schema change.** Ran it on
  all six stories (20/20 throughout) — it's the load-bearing check that the integration host boots
  with the schema/DI shape.
