# Требования: массовое назначение режима перемещения (Bulk Travel Mode)

- **Статус:** Draft
- **Дата:** 2026-06-20
- **Автор:** (через Claude Code)
- **Область:** Trip View → панель «Trip stops»
- **Фича-код:** `TRIP-BULKMODE-01`

---

## 1. Контекст и проблема

В Trip View режим перемещения (`OutgoingTravelMode`) задаётся **отдельно для каждого** перехода (leg) через пер-leg «пилюлю» (`SetLegModeAsync` → `ITripOrderingService.SetOutgoingTravelModeAsync`). Значение хранится в `PoiCollectionItem.OutgoingTravelMode` (null ≡ `AnyAir`).

Фоновый сервис расчёта времени (`TravelTimeComputationBackgroundService`) **считает только наземные режимы** (Walk / Drive / Cycle) и **полностью пропускает** legs в режиме `AnyAir` (FR-21). Поэтому leg в состоянии «Any — set mode» никогда не получает строку кэша `RouteSegment`, его `Fidelity` остаётся `null`, и:

```csharp
// TripViewModel.cs
IsAnyLegComputing = OrderedLegs.Any(l => l.Fidelity is null); // true, пока есть хоть один Any-leg
```

Обе кнопки в шапке панели — **«Sort in Traveling Salesman order»** и **«Recompute travel times»** — заблокированы через `disabled="@Vm.IsAnyLegComputing"` ([TripStopList.razor](../../../LucidCartographer/Components/Shared/Trip/TripStopList.razor)).

**Боль пользователя:** чтобы разблокировать кнопки и получить расчёт, нужно вручную выставить режим **каждому** переходу по одному. Для маршрута из N стопов это N кликов и N выпадающих списков.

**Цель:** дать контрол, который **одним действием** назначает режим перемещения сразу всем переходам маршрута.

---

## 2. Решение (обзор)

Добавить в **шапку панели Trip stops** (рядом с кнопками Sort / Recompute) **массовый селектор режима**:

1. Выпадающий список / сегментированный контрол с режимами: **Drive, Walk, Cycle, Any/Air**.
2. **Чекбокс** рядом, управляющий поведением применения:
   - **выключен (по умолчанию):** применить выбранный режим **только к переходам без режима** (`AnyAir`/null) — не трогать те, где пользователь уже задал режим вручную;
   - **включён:** **перезаписать все** переходы выбранным режимом, включая ранее заданные вручную.
3. По выбору режима — единая операция назначения для всех соответствующих legs, затем обычный refresh проекций + сигнал фонового расчёта (как делает пер-leg путь сегодня).

После назначения наземного режима всем legs фоновый сервис посчитает их время → `Fidelity` перестанет быть `null` → `IsAnyLegComputing` станет `false` → кнопки Sort / Recompute разблокируются.

## 3. Функциональные требования

| ID | Требование |
|----|-----------|
| **FR-1** | В шапке панели Trip stops отображается массовый селектор режима перемещения, когда `Vm.OrderedLegs.Count > 0` (та же видимость, что у кнопок Sort/Recompute). |
| **FR-2** | Селектор предлагает значения: **Drive**, **Walk**, **Cycle**, **Any/Air**. Подписи/иконки согласованы с пер-leg пилюлями. |
| **FR-3** | Рядом с селектором — чекбокс «Перезаписать заданные вручную» (точная подпись — за UX). По умолчанию **выключен**. |
| **FR-4** | При выборе режима с **выключенным** чекбоксом: новый режим присваивается только тем legs, у которых текущий `OutgoingTravelMode` равен `null`/`AnyAir`. Legs с ранее заданным наземным режимом **не изменяются**. |
| **FR-5** | При выборе режима с **включённым** чекбоксом: новый режим присваивается **всем** legs маршрута (включая ранее заданные вручную и Manual-override). |
| **FR-6** | Назначение покрывает **все** directional legs маршрута, в том же составе, что строит `BuildLegs` / `DirectionalPairs`: последовательные k→k+1 **плюс замыкающий** leg на Roundtrip. |
| **FR-7** | Операция **персистится** в `PoiCollectionItem.OutgoingTravelMode` для каждого затронутого стопа через существующий единственный writer (`ITripOrderingService.SetOutgoingTravelModeAsync`) — никакого нового параллельного пути записи. |
| **FR-8** | После назначения VM обновляет проекции (`RefreshProjectionsAsync`) и сигналит фоновый расчёт (`travelTimeTrigger.Signal()`) для наземных режимов — так же, как текущий пер-leg `SetLegModeAsync`. |
| **FR-9** | Выбор **Any/Air** массово сбрасывает legs обратно в `AnyAir` (наземные кэш-строки не пересчитываются; время становится «—»). При этом кнопки Sort/Recompute ожидаемо снова блокируются (это валидное состояние, не ошибка). |
| **FR-10** | Назначение режима **не меняет Stop Order** и не сбрасывает старт/финиш/бюджет — затрагивается только `OutgoingTravelMode`. |
| **FR-11** | Контрол заблокирован во время активного расчёта (`Vm.IsAnyLegComputing`) — по аналогии с кнопками, чтобы массовая операция не накладывалась на незавершённый расчёт. *(Уточнить с UX — см. открытый вопрос Q1.)* |

## 4. Нефункциональные требования

| ID | Требование |
|----|-----------|
| **NFR-1** | Презентационный слой (Razor-компонент) вызывает **только** команду VM и не обращается напрямую к сервисам/БД (консистентно с действующим NFR1 проекта). |
| **NFR-2** | Массовое назначение выполняется как одна логическая операция; промежуточные re-render'ы не «моргают» состоянием кнопок более одного раза. Допустим один общий refresh + один Notify в конце. |
| **NFR-3** | Идемпотентность: повторный выбор того же режима с теми же настройками не создаёт дубликатов строк и не ломает Manual/Measured-гарантии (`UpsertAsync` уже защищает Manual/Measured от авто-даунгрейда). |
| **NFR-4** | Доступность: у селектора и чекбокса есть `aria-label`/`title`; строки — через `UiStrings`. |
| **NFR-5** | Поведение зеркалится в мобильную панель (`MobileTripPanel.razor`) либо явно выносится в tech-debt (см. прошлый дефер mirror-to-mobile). |

## 5. UX-замечания

- Размещение: шапка `TripStopList.razor`, в одном ряду с кнопками Sort / Recompute (`flex items-center gap-1.5`).
- Состояние по умолчанию селектора — плейсхолдер «Set mode for all…» (не выбранное значение), чтобы открытие списка было осознанным действием, а не случайным изменением.
- Чекбокс «Перезаписать заданные вручную» визуально подчинён селектору (мелкий текст), т.к. это модификатор поведения.
- При выборе Any/Air показать ненавязчивую подсказку, что время станет «—» и потребуется ручной ввод (опционально, за UX).

## 7. Критерии приёмки

- **AC-1** Маршрут со всеми legs в «Any — set mode»: выбор «Drive» в массовом селекторе (чекбокс выключен) задаёт Drive всем legs; после фонового расчёта кнопки Sort и Recompute разблокируются.
- **AC-2** Маршрут, где часть legs уже Walk вручную: с **выключенным** чекбоксом выбор «Drive» меняет только Any-legs; Walk-legs остаются Walk.
- **AC-3** Тот же маршрут с **включённым** чекбоксом: выбор «Drive» переводит **все** legs (включая Walk) в Drive.
- **AC-4** Выбор «Any/Air» массово возвращает все legs в Any/Air; время отображается «—»; кнопки Sort/Recompute блокируются.
- **AC-5** Замыкающий leg Roundtrip также получает выбранный режим (FR-6).
- **AC-6** Stop Order, старт/финиш и бюджет времени не изменяются после массового назначения (FR-10).
- **AC-7** Manual-введённое время на leg не затирается фоновым расчётом после массового назначения (NFR-3).
- **AC-8** Все новые/затронутые тесты зелёные; полный прогон Trip-интеграции проходит.
